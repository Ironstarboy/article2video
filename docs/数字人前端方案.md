# 数字人功能的前端方案

> 目标:让网页把"数字人"这件事**说清楚**——开了没有、哪几帧会出人、出了没出、失败了为什么、
> 以及**在没有数字人的预览里怎么看到数字人**。
>
> 前置阅读:`ARCHITECTURE.md` 第七节(数字人链路)、`docs/adr/0001`(为什么预览里看不到数字人)、
> `docs/adr/0002`(圆角投影为什么在叠加时完成)。

---

## 一、现状(代码事实,不是推测)

**创建期**只有一个勾选框:`web/index.html` 的 `#avatar`,提交时 `fd.append("avatar", ...)`,
后端 `POST /api/jobs` 的 `avatar: bool = Form(False)` 落进 `job.state["avatar"]`。

**后端已经有的数字人状态**(`job.to_dict()` 直接返回,前端目前一个都没渲染):

| 字段 | 含义 |
|---|---|
| `state.avatar` | 本任务是否开启数字人 |
| `state.avatar_clips` | 成功生成的片段数(0 表示没生成) |
| `state.avatar_error` | 失败原因(截断 160 字);有值即表示**已静默降级为普通视频** |
| `project/avatar_timeline.json` | 每帧的片段路径、绝对起点、时长 |

**分析结果面板已有的形状**:

- 状态芯片 `#meta-chips`:视频类型 / 文章类型 / 推荐风格 / 总时长 / 来源 —— `index.html:753-761`
- 分析正文 `#analysis-body`(一个 `<pre>`)
- 帧表 `#frames-body`,列为 `["#","类型","画面","旁白","时长","转场"]` —— `index.html:782`
- 动作按钮:构建预览 / 渲染成片 / 重新分析 / 编辑脚本 / AI 修改 / 删除 —— 可用性判定在 `index.html:688-692`
- 预览区:HyperFrames Studio(iframe),渲染完成后换成成片播放器

**结论:数字人目前只在"创建期的那个勾选框"里存在,进入分析结果面板后就完全消失了。**

## 二、缺口清单(按用户误解的严重程度排序)

| # | 问题 | 用户会怎么误解 | 严重度 |
|---|---|---|---|
| 1 | `avatar_error` 前端从不展示 | 数字人失败 → 出的是普通视频 → **以为功能坏了或没生效** | 高 |
| 2 | **Studio 预览里看不到数字人**(ADR-0001 的既定代价) | 构建后预览里没人 → **以为没生成** | 高 |
| 3 | 分析结果里没有"哪几帧会出人"的信息 | 不知道 opening/closing 是无台词的待机帧 → 渲染后才发现"有两段人没说话" | 中 |
| 4 | 渲染后没有确认信息 | 不知道数字人到底叠上去没有,只能靠肉眼找 | 中 |
| 5 | 帧表没有"数字人"列 | 无法把"改了某句台词"与"要重生成哪一帧"对应起来 | 中 |
| 6 | 改一句台词要整片重跑 | 缓存键含音频哈希,本可只重生成该帧,但前端没有入口 | 低 |
| 7 | 形象/位置/尺寸只存在于环境变量 | 想知道"现在用的是哪张图、放哪儿"只能登服务器 | 低 |
| 8 | 片段本身无法预览/下载 | 排查问题时只能进 `.cache/avatar/` 翻文件 | 低 |

## 三、设计原则

1. **诚实优先**。数字人是可选增强,失败可以降级,但**降级必须可见**。宁可显示一条黄色告警,也不要让用户拿到一个"看起来正常、其实没人"的成片。
2. **预览与成片分离是架构事实,不是 bug**。Studio 看不到数字人,就要在预览区**写明白**,并给一个补偿手段(单帧合成预览),而不是把数字人塞回 DOM(`docs/adr/0001` 已否决那条路)。
3. **复用既有形状,不引入新范式**。这个前端是单文件 vanilla JS、无构建步骤:芯片就加芯片、帧表就加列、按钮就加按钮。不引入组件库、不加打包流程。
4. **不暴露用户已经决定不要的东西**。形象固定(金立),前端**不做形象选择器**;换图是运维动作,留接口不留 UI。
5. **失败可续跑**。任何一环失败只重跑那一环,不从头再来。

## 四、方案

### 4.1 分析结果面板(核心改动,零新接口)

**新增一枚状态芯片**,与现有五枚并列:

| 情形 | 芯片文案 | 样式 |
|---|---|---|
| 本任务未开数字人 | 不显示(保持界面与既有任务完全一致) | — |
| 已开启、尚未构建 | `数字人:已开启` | 普通 |
| 已构建成功 | `数字人:6 段(说话 4 · 待机 2)` | 普通 |
| 构建失败 | `数字人:失败(原因摘要)` | 警示色 |

数据全部来自 `job.state`,**不需要新接口**。

**帧表新增一列"数字人"**(插在"旁白"之后):

- 有 `voiceover` → `说话`
- 无 `voiceover`(opening/closing 等) → `待机`
- 未开启数字人的任务 → 整列不显示

判定逻辑纯前端即可(`frames[].voiceover` 是否为空),与后端 `build_frame_clips` 的判定规则一致
(`server/avatar.py`:有台词且配音文件存在 → 说话片段,否则 → 待机片段)。

### 4.2 预览区的诚实提示(一行字,防误解)

Studio 预览区加固定说明:

> 预览里看不到数字人:数字人是在**渲染成片之后**由 ffmpeg 叠加的(见 `docs/adr/0001`)。
> 想确认效果,用下面帧表的「合成预览」。

### 4.3 单帧合成预览(本方案里唯一必须新增的接口)

**这是整个方案的关键**:它把"预览看不到数字人"这个结构性盲区补上了。

- 接口:`GET /api/jobs/{id}/avatar/preview/{frame_index}` → 返回 PNG
- 实现:该帧渲染起点对应的**成片静帧**(若未渲染,则用项目里该帧的静态渲染)与**该帧数字人片段的首帧**,
  按 `TTV_AVATAR_X/Y` 与圆角遮罩合成一张图(复用 `avatar.card_overlay_filter`,单帧 ffmpeg,毫秒级)
- 前端:帧表每行加「预览」按钮 → 弹层显示;未构建时按钮禁用并提示"先构建"

价值:这是用户**唯一能提前看到数字人效果**的途径,而且成本极低。

### 4.4 渲染后

- 芯片更新为 `数字人:已叠加 6 段`
- 若本次渲染叠加失败(`avatar_error`):下载区上方显示**黄色告警条** + 「只重跑数字人」按钮
- 告警条文案要给出下一步:"数字人未叠加,成片仍是完整的 PPT 视频。修复后点「只重跑数字人」再渲染。"

### 4.5 只重跑数字人 / 单帧重生成

- 按钮「只重跑数字人」(`POST /api/jobs/{id}/avatar/rebuild`,可带 `frame_index`)
- 语义:按需失效缓存(不传帧号则清空该任务的数字人缓存;传帧号只清该帧),重算时间轴,状态回到 `preview`
- 前端提示:"数字人已重跑,请重新渲染成片"
- 帧表每行(仅"说话"行)也提供「重生成」,走同一个接口

### 4.6 形象与位置(运维向,最后做)

- `GET /api/avatars` 暴露 `builder/styles.py` 的 `AVATARS` 注册表(键/名/图)
- 设置区(非主流程)显示**当前形象缩略图**与文件名,并说明换图方式(`assets/avatars/` 替换或 `TTV_AVATAR_IMAGE`)
- 位置/尺寸:若要给前端调,再补 `PATCH /api/jobs/{id}/avatar {x,y,size}`;第一版**不给**,用后端默认(40,36,320)

## 五、接口汇总

| 方法 | 路径 | 用途 | 优先级 | 备注 |
|---|---|---|---|---|
| — | — | 芯片/帧表/告警 | **P0** | **纯前端,零新接口**(`to_dict()` 已带全部字段) |
| GET | `/api/jobs/{id}/avatar/preview/{frame}` | 单帧合成预览 PNG | **P0** | 唯一必需的新接口 |
| POST | `/api/jobs/{id}/avatar/rebuild` | 重跑数字人(可指定帧) | P1 | 复用现有 `avatar.build_frame_clips` |
| GET | `/api/jobs/{id}/avatar/clip/{frame}` | 下载单段片段 | P2 | 调试用 |
| GET | `/api/avatars` | 形象注册表 | P2 | 只读 |

## 六、分阶段实施

**P0(约半天,收益最大)**
1. `#meta-chips` 加数字人芯片(含失败告警色)
2. 帧表加"数字人"列
3. Studio 预览区加说明文字
4. `avatar_error` 告警条
5. `GET /api/jobs/{id}/avatar/preview/{frame}` + 帧表「预览」按钮与弹层

**P1(约 1 天)**
6. 「只重跑数字人」按钮与接口
7. 渲染后的"已叠加 N 段"确认与失败引导

**P2(1-2 天)**
8. 单帧重生成入口
9. 片段下载
10. 形象/位置设置区

## 七、明确不做(以及理由)

- **不做形象选择器**:需求方已定"固定一个形象,不给用户选"。做了就是给用户制造一个不需要的决策。
- **不做逐字口型对齐可视化**:数字人片段就是由该帧**同一个配音文件**驱动的(`docs/adr/0002` 与 `CONTEXT.md` 的"数字人片段"),
  时间轴天然唯一,可视化对齐没有收益。
- **不做前端拖拽调位置**:一次配置的事,拖拽要引入 1080p 画布坐标换算与缩放,复杂度远高于收益。
- **不把数字人写进渲染 DOM**:`docs/adr/0001` 已评估并否决(要将逐帧精确性押在 headless Chrome 的解码与寻址行为上)。
- **不新增前端框架/构建步骤**:与项目"单文件、无构建"的现状冲突。

---

## 八、验收标准

1. **未开数字人的任务**:界面与改动前**完全一致**(不出现任何空芯片或空列)。
2. **开启数字人、分析完成后**:芯片显示 `数字人:已开启`,帧表出现"数字人"列且逐帧标注正确
   (有台词的帧标"说话",opening/closing 标"待机")。
3. **数字人服务未启动时构建**:芯片显示失败原因摘要,告警条给出下一步,**且普通成片仍可正常产出**(保持现有降级行为)。
4. **渲染完成后**:芯片显示 `数字人:已叠加 N 段`,N 与时间轴条目数一致。
5. **单帧预览**:能打开弹层并看到圆角卡片叠加在画面左上角的效果。
6. **只重跑数字人**:不清空配音与脚本,状态回到 `preview`,可再次渲染。
