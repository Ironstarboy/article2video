# 数字人播报视频走独立拼接管线，而不是并入成片渲染

需求是「分析好章节后就能单独渲染数字人的播报视频，有按钮、有生成步骤和预计时间，完成后能单独预览」。
成片（PPT 画面 + 左上角数字人叠加）已经是一条成熟链路，但它必须等**构建（配音+组装）**再等**渲染（Chrome 抓帧 + 编码）**，
分析刚结束的用户在十几分钟内拿不到任何视频。

我们决定：播报视频**不复用成片链路**，而是把各帧数字人片段按时间轴顺序 concat，再合上按同一时间轴拼出的配音音轨，
产出一条独立的 320×320 视频（`renders/avatar.mp4`），由 `POST /api/jobs/{id}/avatar/broadcast` 单独触发。

## Considered Options

- **并入成片渲染，先出无人像版再补人像**：产物仍然只有一条，用户要等到 PPT 渲染完成。
  而 PPT 渲染正是最慢、最容易失败（`capture_disk` 预检）的一段 —— 把「看数字人」押在它后面，等于把这条需求的价值让掉。
- **在 Studio 里单独预览人像**：人像不在渲染 DOM 里（见 ADR-0001），Studio 里根本没有它；要做就得回到 ADR-0001 已经否决的路。
- **独立拼接管线（选中）**：只需要配音 + 片段 + 一次 concat，分钟级（长片十几分钟）出片，
  与 Chrome、与磁盘预检、与 Studio 生命周期全部解耦；片段缓存与成片共用，两条轨道画面必然一致。

## Consequences

- 任务多了一个产物 `state.artifacts.avatar` 与一个进行中状态 `avatar_building`（计入 `MAX_INFLIGHT_JOBS`，且重启置 failed 可重跑）。
- 播报视频与成片是**两条轨道**：改了脚本要各自重新生成。界面上用「脚本改动时间 vs 视频生成时间」提示过期，不自动重跑。
- 配音可能被合成两次：先点播报、之后再点构建时，`stage_build` 会删掉配音目录重合成。
  用 `state.vo_sig`（逐帧台词 + 音色 + 引擎的摘要）把「同一份脚本」变成可复用的前提，重跑不再烧 GPU；这是本决策明确接受的代价。
- 播报视频的时长按片段**真实时长**铺音轨（逐片段 ffprobe），不按声明帧时长：
  否则毫秒级差异逐帧累积，会让 `-shortest` 从片尾裁掉台词。
