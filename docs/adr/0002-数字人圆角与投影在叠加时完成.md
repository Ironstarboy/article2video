# 数字人的圆角与投影在叠加时完成，不烘焙进片段

最初的设计是"把圆角与投影烘焙进片段本身，叠加时只做一次干净 overlay"。
实现时发现:**H.264 不支持 alpha**——烘焙后的片段在透明区会变成黑底,叠到幻灯片上就是个黑框。
要保留 alpha 只能换 prores/qtrle 这类中间格式,片段体积从约 300KB 涨到几十 MB,且缓存要长期保留这些片段。

因此改为:片段保持**纯净的 320×320 H.264**(不带圆角、不带投影),
圆角与投影在**渲染后的叠加步骤**里用同一张灰度遮罩 + boxblur 完成,整体仍是一次 ffmpeg 滤镜图。

## Considered Options

- **烘焙进片段 + alpha 中间格式(prores/qtrle)**:叠加最简单,但片段大 30 倍以上,缓存与 IO 代价高。
- **烘焙进片段 + 固定底色**:底色与幻灯片背景不一致时会出现可见色框,不可接受。
- **叠加时做遮罩(选中)**:片段小、缓存轻;代价是叠加用的滤镜图更复杂(圆角遮罩 + 投影 + PTS 平移)。

## Consequences

- 叠加步骤必须把卡片流的 PTS 平移到帧起点(`setpts=PTS-STARTPTS+start/TB`),
  否则叠加窗口内播放的是片段自身时间轴的末尾——这是本方案最容易踩的坑。
- 圆角遮罩必须用**亮度**编码形状(灰度图):ffmpeg 的 `alphamerge` 取的是第二路输入的亮度,
  而不是它的 alpha 通道;用 RGBA 白底遮罩会等价于处处不透明,圆角静默失效。
- 修改圆角半径/投影参数需递增 `TTV_AVATAR_CLIP_VERSION`,否则遮罩名不变、旧遮罩被复用。
