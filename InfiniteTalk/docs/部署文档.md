# InfiniteTalk 在 PPU-ZW810E 上的部署文档

> 基于 MeiGen-AI/InfiniteTalk 项目，在阿里云 PAI/DSW（cn-wulanchabu）8 × T-HEAD PPU-ZW810E 环境下的从零部署指南。

---

## 1. 环境概览

| 项目 | 说明 |
|------|------|
| **地域** | `cn-wulanchabu`（乌兰察布） |
| **实例** | PAI/DSW，8 × T-HEAD PPU-ZW810E（每卡 48GB HBM2e） |
| **基础镜像** | `egslingjun-registry.cn-wulanchabu.cr.aliyuncs.com/egslingjun/inference-xpu-pytorch:26.04-v2.1.0-vllm0.23.0-torch2.10-cu130-20260710` |
| **项目仓库** | https://github.com/MeiGen-AI/InfiniteTalk |
| **许可证** | Apache-2.0 |
| **模型权重** | 从 HuggingFace 下载，总计约 88GB |

> ⚠️ **关键结论（踩坑得出，务必先读附录 A）**：PPU-ZW810E **不是**通用 CUDA 设备。
> 必须使用**厂商定制的 PPU 版 PyTorch**（`torch==2.10.0+ppu2.1.0`），
> 公版 `pytorch.org` 的 torch（无论 cu121/cu128/cu130）**都无法驱动 PPU**，
> 而且**每次运行前必须 `source /usr/local/PPU_SDK/envsetup.sh`**。
> 详见文末 [附录 A：PPU 环境搭建要点](#附录-a-ppu-环境搭建要点)。

## 2. 准备工作

### 2.1 磁盘空间检查

创建 DSW 实例前，确保持久化盘 ≥ **200GB**（模型 88GB + 缓存 + 代码 + 留余量）。

```bash
df -h /mnt/workspace/ | tail -1
# 确认 Available > 200G
```

如果持久化盘小于 200GB，请在 PAI 控制台创建实例时选择更大的持久化盘。

### 2.2 安装 Miniconda（如果系统未预装）

```bash
which conda || (
  wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O /tmp/miniconda.sh
  bash /tmp/miniconda.sh -b -p $HOME/miniconda3
  eval "$($HOME/miniconda3/bin/conda shell.bash hook)"
  conda init
)
```

### 2.3 创建 DSW 实例

在阿里云 PAI 控制台的 cn-wulanchabu 地域创建 DSW 实例：

- **卡数**：选择 `8` 卡（支持的选项: 1, 2, 4, 8, 16）
- **镜像**：根据上文"路径 A / 路径 B"选择对应镜像
- **持久化盘**：≥ **200GB**
- **端口转发**（可选，如需通过浏览器远程访问 Gradio）：
  - 在 DSW 实例详情 → 服务访问配置中，添加 HTTP 服务
  - 监听端口 `7860`（Gradio 默认端口），公开端口任意
  - 如需 SSH 连接：端口 `22`

### 2.4 存储规划

| 存储位置 | 用途 |
|---------|------|
| `/mnt/workspace/`（持久化盘） | 模型权重、数据集、项目代码、日志 |
| `/dev/shm/`（内存盘，临时） | 编译缓存、Triton/TorchInductor 缓存、ZeroMQ IPC 端点 |

> `/dev/shm` 是临时内存盘，容器重启后会清空。仅用于存放编译缓存，**不要**把模型权重放在这里。

## 4. 安装依赖

### 4.1 创建 Conda 环境（推荐）

```bash
conda create -n infinitetalk python=3.10 pip -y
conda activate infinitetalk
```

**注意**：每次新开终端都要执行 `conda activate infinitetalk` 激活环境。

### 4.2 安装 PyTorch

> 如果使用 **路径 A（PPU 镜像）**，镜像内置了 PyTorch 2.10，**跳过此节**。
>
> 如果使用 **路径 B（通用 CUDA 镜像）**，按以下步骤安装：

```bash
# CUDA 12.1
pip install torch==2.4.1 torchvision==0.19.1 torchaudio==2.4.1 --index-url https://download.pytorch.org/whl/cu121
```

验证：

```bash
python -c "import torch; print('torch:', torch.__version__); print('CUDA:', torch.cuda.is_available()); print('Device count:', torch.cuda.device_count())"
```

- 如果输出 `CUDA: False` 但 `Device count: 4`，说明 PPU 驱动兼容但 CUDA API 初始化有顺序问题，**不影响实际推理时使用**。
- 如果输出 `Device count: 0`，检查 `nvidia-smi` 是否可用，或使用 `CUDA_DEVICE_ORDER=PCI_BUS_ID` 环境变量。

## 5. 下载模型权重

需要下载以下三组模型权重，总计约 **88GB**。建议在 **tmux** 或 **screen** 会话中执行，防止 SSH 断连导致下载中断。

```bash
tmux new -s download_model
# 在下方的下载命令完成后，按 Ctrl+B 然后按 D 分离会话
# 之后用 tmux attach -t download_model 恢复
```

### 5.1 Wan2.1-I2V-14B-480P（基础模型，~67GB）

> 这是 Wan 视频生成的基础模型，InfiniteTalk 在其上做微调。

**方式一：HuggingFace 镜像站（推荐，国内更快）**

```bash
cd /mnt/workspace/
mkdir -p weights

export HF_ENDPOINT=https://hf-mirror.com
# 如果需要访问受限模型，先登录
huggingface-cli login --token hf_你的token

huggingface-cli download Wan-AI/Wan2.1-I2V-14B-480P --local-dir ./weights/Wan2.1-I2V-14B-480P
```

**方式二：ModelScope 国内下载**

```bash
pip install modelscope
# 登录 ModelScope
modelscope login --token YOUR_MODELSCOPE_TOKEN

export MODELSCOPE_DOWNLOAD_INTRA_CLOUD_REGION=cn-wulanchabu
modelscope download Wan-AI/Wan2.1-I2V-14B-480P --local-dir ./weights/Wan2.1-I2V-14B-480P
```

**下载后验证：**

```bash
ls -lh /mnt/workspace/weights/Wan2.1-I2V-14B-480P/
# 应有：
# - diffusion_pytorch_model-00001-of-00007.safetensors (9.2GB)
# - diffusion_pytorch_model-00002-of-00007.safetensors (9.1GB)
# - ... 共 7 个分片
# - Wan2.1_VAE.pth (484MB)
# - config.json
# - google/umt5-xxl/ (T5 编码器)
# - xlm-roberta-large/ (CLIP 编码器)
```

> **断点续传**：`huggingface-cli download` 会自动续传中断的下载。如果下载中断，直接重新执行同样的命令即可，不会重新下载已完成的分片。

## 6. 运行推理

> 每次新开终端，先激活环境：
>
> ```bash
> conda activate infinitetalk
> cd /mnt/workspace/ttv/InfiniteTalk/code
> ```

### 6.1 单 GPU 推理（480P 图像/视频配音）

```bash
python generate_infinitetalk.py \
    --ckpt_dir ../weights/Wan2.1-I2V-14B-480P \
    --wav2vec_dir ../weights/chinese-wav2vec2-base \
    --infinitetalk_dir ../weights/InfiniteTalk-int8/quant_models/infinitetalk_single_int8.safetensors \
    --quant int8 \
    --input_json examples/single_example_image.json \
    --size infinitetalk-480 \
    --sample_steps 40 \
    --mode streaming \
    --motion_frame 9 \
    --save_file infinitetalk_res
```

> `--quant int8` 只在 `infinitetalk_dir` 指向 INT8 权重时使用。如果用的是全精度权重，去掉这个参数。

**输出**：在当前目录生成 `infinitetalk_res.mp4` 等视频文件。

### 6.2 720P 推理

```bash
python generate_infinitetalk.py \
    --ckpt_dir ../weights/Wan2.1-I2V-14B-480P \
    --wav2vec_dir ../weights/chinese-wav2vec2-base \
    --infinitetalk_dir ../weights/InfiniteTalk-int8/quant_models/infinitetalk_single_int8.safetensors \
    --quant int8 \
    --input_json examples/single_example_image.json \
    --size infinitetalk-720 \
    --sample_steps 40 \
    --mode streaming \
    --motion_frame 9 \
    --save_file infinitetalk_res_720p
```

> 720P 模式使用与 480P 相同的基础模型（Wan2.1-I2V-14B-480P），模型内部做分辨率上采样，**不需要**独立的 720P checkpoint。

### 6.3 低显存模式（24GB 以下显卡）

```bash
python generate_infinitetalk.py \
    --ckpt_dir ../weights/Wan2.1-I2V-14B-480P \
    --wav2vec_dir ../weights/chinese-wav2vec2-base \
    --infinitetalk_dir ../weights/InfiniteTalk-int8/quant_models/infinitetalk_single_int8.safetensors \
    --quant int8 \
    --input_json examples/single_example_image.json \
    --size infinitetalk-480 \
    --sample_steps 40 \
    --num_persistent_param_in_dit 0 \
    --mode streaming \
    --motion_frame 9 \
    --save_file infinitetalk_res_lowvram
```

### 6.4 多 GPU 推理（8 卡 PPU）

```bash
GPU_NUM=8

# 设置 NCCL 环境变量（PPU 环境需要）
export NCCL_DEBUG=WARN
export NCCL_SOCKET_IFNAME=eth0

torchrun --nproc_per_node=$GPU_NUM --standalone generate_infinitetalk.py \
    --ckpt_dir ../weights/Wan2.1-I2V-14B-480P \
    --wav2vec_dir ../weights/chinese-wav2vec2-base \
    --infinitetalk_dir ../weights/InfiniteTalk-int8/quant_models/infinitetalk_single_int8.safetensors \
    --dit_fsdp --t5_fsdp \
    --ulysses_size=$GPU_NUM \
    --input_json examples/single_example_image.json \
    --size infinitetalk-480 \
    --sample_steps 40 \
    --mode streaming \
    --motion_frame 9 \
    --save_file infinitetalk_res_multigpu
```

### 6.5 Gradio Web 界面

```bash
python app.py \
```

## 8. 故障排除

### 8.1 模型下载慢

```bash
# 使用 HuggingFace 镜像站
export HF_ENDPOINT=https://hf-mirror.com

# 如果需要访问受限模型，设置 token
huggingface-cli login --token hf_你的token

# 推荐在 tmux 中下载，防止 SSH 断连
tmux new -s download
# ... 执行下载 ...
# Ctrl+B, D 分离；tmux attach -t download 恢复
```

### 8.2 磁盘空间不足

```bash
# 下载前检查
df -h /mnt/workspace/

# 查看模型权重大小
du -sh /mnt/workspace/weights/
# 总大小约 88GB

# 清理无效缓存
rm -rf /mnt/workspace/weights/*/.cache/huggingface/download/*/
```

### 8.3 CUDA 初始化报警告

```
UserWarning: CUDA initialization: Unexpected error from cudaGetDeviceCount()
```

**原因**：PPU 的 CUDA 兼容层与标准 CUDA 初始化顺序有差异。

**解决方案**：
- 此警告**不影响推理**，可忽略
- 如需消除，设置环境变量：

```bash
export CUDA_DEVICE_ORDER=PCI_BUS_ID
```

### 8.4 xfuser / diffusers 版本冲突

**症状**：`ImportError: cannot import name 'SanaAttnProcessor2_0'`

**原因**：系统已预装的 PPU xfuser 版本与手动安装的 diffusers 版本不匹配。

**解决方案**：

- **路径 A（PPU 镜像）**：使用系统预装的 PyTorch/xfuser，不要手动覆盖安装
- **路径 B（通用镜像）**：在独立的 conda 环境中安装，版本链为：
  ```
  torch 2.4.1 → diffusers 0.32.2 → xfuser 0.4.x → peft < 0.14
  ```
  具体命令：
  ```bash
  conda activate infinitetalk
  pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu121
  pip install "diffusers>=0.27.0,<0.33.0" "peft>=0.11.0,<0.14.0" "accelerate>=0.33.0"
  pip install "xfuser>=0.4.1,<0.5.0"
  pip install -r requirements.txt
  ```

InfiniteTalk 核心模型加载逻辑 (`wan/multitalk.py`) 不依赖 xfuser 初始化。只有多 GPU 分布式推理时才会用到 xfuser。

### 8.5 OOM（显存不足）

- 使用 `--num_persistent_param_in_dit 0` 最低显存模式
- 使用 INT8 量化权重（比 FP16 省约 60% 显存）
- 降低分辨率 `--size infinitetalk-480`（720P 需更多显存）
- 减少 `--motion_frame` 值（默认 9）
- 使用 `--offload_model True`（如果脚本支持，将部分层卸载到 CPU）

### 8.6 phonemizer 安装失败

`pip install phonemizer` 需要系统级依赖 `espeak-ng`：

```bash
apt-get update && apt-get install -y espeak-ng
# 或 yum install -y espeak-ng
```

## 附录 A：PPU 环境搭建要点

> 这是本项目在 PPU-ZW810E 上实际跑通后总结的**核心经验**，比前面章节更重要。

### A.1 PPU 不是通用 CUDA 设备

PPU（T-HEAD ZW810E）通过一层 CUDA 兼容层工作，但**公版 PyTorch 无法驱动它**。实测结论：

| PyTorch 版本 | 结果 |
|--------------|------|
| `2.4.1+cu121`（公版） | ❌ `cudaGetDeviceCount` 返回 invalid argument |
| `2.5.1+cu121`（公版） | ❌ 同上 |
| `2.10.0+cu130`（公版） | ❌ 同上（且与 PPU 的 libnccl/cudart 符号冲突） |
| `2.10.0+ppu2.1.0`（**厂商版**） | ✅ 4 卡识别，96GB/卡，运算正常 |

**根因**：公版 torch 自带 pip 版 CUDA 运行时（`nvidia-*-cu13`），它与 PPU 的 `libcuda.so.1` 兼容层不兼容；
而 PPU 自带的 `libcudart` 又缺少公版 torch 需要的符号（如 `__cudaGetKernel`）。两者必须配套。

### A.2 厂商 PyTorch 的下载源

厂商适配的 PPU 版 PyTorch / xformers 托管在阿里云 AI 扩展源：

```
https://aiext-pypi.mirrors.aliyuncs.com/pg1-pip/generic/
```

浏览可用版本（以 torch 为例）：

```bash
curl -s "https://aiext-pypi.mirrors.aliyuncs.com/pg1-pip/generic/torch/" | grep -oE '2\.[0-9]+\.[0-9]+%2B[^/]+/'
```

**命名规则**：`<torch版本>+<cuda>torch<torch版本><系统><oe/ce>-cp<py版本>-...`

- `ubuntu2404` = Ubuntu 24.04（本机），`alios7u2` = 阿里云 Linux
- `oe` = 厂商定制后缀
- **注意**：PPU 版 torch 2.10.0 只提供 **cp312**（Python 3.12）

下载示例（本次实际使用）：

```bash
B="https://aiext-pypi.mirrors.aliyuncs.com/pg1-pip/generic"
```

PPU 版 torch 的依赖里**没有任何 `nvidia-*` pip 包** —— 它直接使用 PPU SDK 的系统库。这是判断是否装对的重要标志。

### A.3 必须 source PPU 环境脚本

**每次运行前**都要执行（否则 CUDA 不可用）：

```bash
source /usr/local/PPU_SDK/envsetup.sh
```

它会设置 `PPU_SDK` / `CUDA_HOME` / `LD_LIBRARY_PATH` 等变量，让 torch 找到 PPU 的 `libcuda.so.1`。

可用 `CUDA_SDK` 模式（默认）或 PPU 模式（`source envsetup.sh ppu`），推理用默认即可。

### A.4 验证 PPU 是否正常

```bash
source /usr/local/PPU_SDK/envsetup.sh
python3 -c "
import torch
print('torch:', torch.__version__)
print('CUDA:', torch.cuda.is_available(), torch.cuda.device_count())
print('name:', torch.cuda.get_device_name(0))
x = torch.randn(1000,1000).cuda(); print('运算:', (x@x).shape)
```

### A.6 不要污染系统 Python 环境

系统 Python（`/usr/local/bin/python3`）被 ComfyUI、TTS 服务等多个服务共用。
给本项目装依赖时**务必用独立 venv**，且**不要把系统 torch 换成公版**：

```bash
cd /mnt/workspace/ttv/InfiniteTalk
python3 -m venv --system-site-packages .venv-it   # 继承系统的 PPU torch
.venv-it/bin/pip install -r InfiniteTalk-main/requirements.txt
```

> `--system-site-packages` 是关键：让 venv 复用系统已装好的 PPU torch，避免重复安装/覆盖。

### A.7 项目源码的 Python 3.12 兼容补丁

`wan/multitalk.py` 第 3 行 `from inspect import ArgSpec` 在 Python ≥3.11 会报
`ImportError`（该名称已被移除）。此行**未被使用**，直接删除即可：

```bash
sed -i '/^from inspect import ArgSpec$/d' wan/multitalk.py
```

### A.8 量化必须用 fp8，不能用 int8

仓库只提供 `t5_fp8.safetensors`（**没有** `t5_int8.safetensors`），
而代码按 `--quant` 的值拼 T5 权重文件名：

```python
model_state_dict = load_file(os.path.join(quant_dir, f"t5_{quant}.safetensors"))
```

因此 `--quant int8` 会因为找不到 `t5_int8.safetensors` 而失败。
**必须使用 `--quant fp8` + `--quant_dir .../infinitetalk_single_fp8.safetensors`。**

